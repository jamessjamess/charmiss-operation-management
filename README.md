## Data Adapter Ops → Supply (CR-01 ข้อ 6 · Phase B) — `supply-feed.js`

อ่านอย่างเดียว: สร้างตาราง Supply ใหม่จากสถานะของ Ops ทุกครั้ง (ไม่สะสม) — ดึงซ้ำกี่ครั้งได้ตารางเท่าเดิม และ Event ID เดิมนับครั้งเดียว · ไม่เขียนออเดอร์ Quota เอกสาร หรือ WMS · ใช้กับชุด **Integrated demo** เท่านั้น (UAT seed คนละ SKU / คู่ค้า)

**ตัดข้อมูลที่รอบดึง WMS ล่าสุด** (`db.wmsSnapshot.asOf`): WH, ระหว่างขนส่ง, Sales In และ CN ตัดที่เวลาเดียวกัน ของชิ้นหนึ่งจึงอยู่ที่ใดที่หนึ่งเท่านั้น (ใน WMS / ระหว่างขนส่ง / ส่งถึงแล้ว) — ธุรกรรมหลังรอบดึงจะเห็นหลังกด "ดึงยอด WMS" · ทุกหน้า Supply แสดง "ข้อมูล Ops ณ <เวลา> · WMS version <n>" และจำนวนธุรกรรม

- **ชุด Integrated demo (ตอนเริ่มชุด):** Quota ของ Ops เดือน พ.ย. 2026 = Quota ของ Supply เดือนเดียวกัน (953 คู่ อนุมัติแล้ว) · "ใช้ไปยกมา" = Sales In ต้นเดือนถึง 22 พ.ย. (168,591 ชิ้น) และนับกลับเข้า "ส่วนกลางโควตา" เหมือนของที่ WMS ส่งแล้ว · Quota สาธิตเดิมของช่องทาง Direct / Social คงไว้ · ตัวอย่างคำขอเพิ่ม Quota รออนุมัติ 1 ใบ (AL-260014)
- **WMS DEMO ของ Integrated demo:** ปุ่มดึงยอด WMS คืนยอด = ยอดเริ่ม − ของที่ส่งมอบขนส่งแล้ว + ของคืนสภาพดีที่ WMS รับแล้ว (จำลองระบบ WMS จริง) — Ops ยังแค่ **อ่าน** ผ่าน `wmsApplySnapshot` เดิม · ชุด UAT seed ใช้ WMS DEMO เดิม
- **ออเดอร์ที่ออกจากคลังก่อนเริ่มชุด** ถือเป็นประวัติเดิม ไม่ถูกนำเข้าซ้ำ
- Quota สาธิตของ Ops ที่ถูกแทนด้วย Quota จริงถูกจดไว้ใน `db.retiredSeeds` — ตัว Seed ตอนโหลดหน้าของโมดูล E-commerce (เดิมใช้รหัส `16160` / `16310`) จะไม่สร้างกลับมาอีก
- `account_master` ใช้ account_id ชุดเดียวกับคู่ค้าของ Ops (ตั้งตอนเริ่มชุด) · Safety Units (Ecom) ของ Ops เก็บแยกใน Product master ไม่ปนกับ Safety Days (ROP) ของ Supply
- **AS OF:** ถ้ามีธุรกรรม Ops แล้ว AS OF ล่าสุด = วันจันทร์ถัดจากรอบดึง WMS (เช่น 30 พ.ย. 2026) และเป็นค่าเริ่มต้น · AS OF 23 พ.ย. ยังให้ตัวเลข Anchor เดิมทุกค่า (ย้อนคำนวณจาก Snapshot ใหม่ได้ตรง)
- **Run Rate** คิดถึงสัปดาห์สุดท้ายของประวัติ Integrated demo เท่านั้น (สัปดาห์หลังจากนั้นมีแต่ธุรกรรมสาธิต — ถ้านับจะทำให้ Run Rate ตกผิดจริง)
- **selfCheck ใหม่ (6.3):** (7) WH ของ Supply = WMS Actual ทุก SKU · (8) Σ Sales In ของงวด = Σ ออเดอร์ Delivered ของงวด · (9) Quota จัดสรร / จอง / หักจริง = Ops ทุกคู่ค้า × SKU × เดือน — แสดงที่หน้า ข้อมูล & ตั้งค่า Supply และ Console

### F5 In-transit · F6 CN Good / Bad · F9 Clearance
- **F5:** การ์ดมูลค่า Stock มีส่วน "ระหว่างขนส่ง" · Projection มีชั้นที่ 3 (ของถึงคู่ค้าตาม Delivery lead days ของคู่ค้า) · ตาราง Stock มีคอลัมน์ระหว่างขนส่ง · Waterfall และ selfCheck ข้อ 4 รวมระหว่างขนส่งใน Total (แสดงเมื่อมีของระหว่างขนส่ง)
- **F6:** คลังตรวจรับคืนต้องแยก ดี + เสีย ให้ครบจำนวน (เดิม) และ**ต้องใส่เหตุผลเมื่อมีของเสีย** (ใหม่) · หน้ารับคืนจาก WMS แสดงสภาพ · ฝั่ง Supply: Good = กลับเข้า WH · Bad = Write-off
- **F9:** Admin › รายการสินค้า › ตั้ง / แก้ไขสินค้า มีช่อง "สถานะสินค้า (Supply)" New / Active / Discontinue / Clearance (บันทึก Audit) · Clearance ไม่ขึ้นเสี่ยงขาด / สั่งผลิตเลย, Suggested Qty = 0, คำแนะนำ "ขายเคลียร์"

### calc.js ที่แก้ (ทุกจุดมี `// CR-01`)
`prepare` อ่าน `in_transit`, `quota.reserved_qty / committed_qty`, `_history_end` · `itAt()` ใหม่ · `stockAt` แยกระหว่างขนส่งออกจาก WH · `skuRow` / `projectSku` / `seriesOf` / `waterfallOf` / `skuDetail` / `replenList` / `selfCheck` (reconcile) รวมระหว่างขนส่ง · `runRate` หยุดที่ปลายประวัติ · สถานะ Clearance (`skuRow`, `recommend`, `replenList`) — สูตรเดิมทั้งหมดไม่เปลี่ยน เมื่อไม่มีธุรกรรม Ops ผลลัพธ์เท่าเดิมทุกตัว

### R3 Run Rate ไม่นับสัปดาห์ที่ของขาด — สวิตช์ `rrMode` (`unconstrained` ใหม่ · `sellout` เดิม)
- **สัปดาห์ที่ของขาด (OOS)** ต่อ SKU × คู่ค้า (`Calc.oosOf`):
  - ฝากขาย: Remaining ต้นสัปดาห์ ≤ `oosUnits` (0) หรือ < ยอดขาย 1 วัน (เฉลี่ย 26 สัปดาห์ก่อนหน้า)
  - ขายขาด / Ecom: WH พร้อมขาย (WH − Safety units ของ Ops) ต้นสัปดาห์ ≤ 0
  - **เพิ่มจากเอกสาร — `oosEnd` (เปิดเป็นค่าเริ่มต้น ปิดได้):** สัปดาห์ที่ของหมดก่อนสิ้นสัปดาห์ (ต้นสัปดาห์ถัดไปถึงเส้นเดียวกัน) ก็นับเป็นของขาด — เกณฑ์ต้นสัปดาห์อย่างเดียวพลาดสัปดาห์ที่ของหมดกลางสัปดาห์ (เช่น CM-FD-003 สัปดาห์ 12 ต.ค. ขาย 0 แต่ต้นสัปดาห์ยังมีของ)
  - นับเฉพาะคู่ที่มียอดขายใน 26 สัปดาห์ก่อนหน้า (สินค้าที่ยังไม่วางขายไม่ใช่ของขาด)
- **Run Rate (Unconstrained)** (`Calc.runRateU`) = Σ Sales Out สัปดาห์ที่มีของ ÷ จำนวนสัปดาห์ที่มีของ · ใช้ได้ทุก Basis (L4W / L3M / L6M / Weighted) และจุดหยุดเดียวกับ R1
  - สัปดาห์ที่มีของน้อยกว่า 2 → ขยายย้อนหลังทีละ 4 สัปดาห์ (สูงสุด 26) · ยังไม่พอ → Sell-out เดิม
  - **ไม่ต่ำกว่า Sell-out** — ความต้องการจริงไม่น้อยกว่ายอดที่ขายได้ (สัปดาห์ที่ของขาดบางสัปดาห์ยังขายได้มากหลังของเข้า)
  - หน้าต่างที่ไม่มีสัปดาห์ของขาด → เท่า Sell-out เป๊ะ (ชุดสาธิต: 902 คู่เท่าเดิม · 41 คู่สูงขึ้น · 10 คู่เท่าเดิมเพราะเพดานล่าง · ไม่มีคู่ที่ต่ำลง)
- **Lost sales** ต่อ SKU × คู่ค้า = max(0, Run Rate × วันที่ของขาด − Sales Out ของสัปดาห์เหล่านั้น) × ราคาสุทธิของคู่ค้า — 13 สัปดาห์ (คอลัมน์) · 4 สัปดาห์ (การ์ดภาพรวม)
- **สวิตช์:** ตั้งค่า Supply › Run Rate และ Filter bar › **วิธี Run Rate** (ลิงก์มี `rm=` เมื่อไม่ตรงค่าตั้ง)
- **แสดงผล:**
  - Stock & Projection: คอลัมน์ **สัปดาห์ OOS (13W)** + **Lost sales 13W**
  - Drawer SKU: กราฟ **Sales Out รายสัปดาห์ 26 สัปดาห์** (สัปดาห์ที่ของขาด = แท่งแดง · เส้น Run Rate ไม่นับช่วงของขาด)
  - ภาพรวม Supply: การ์ด **Lost sales 4 สัปดาห์ล่าสุด** (รวม + 5 SKU ที่เสียมากสุด → เปิด Drawer)
  - ฝากขาย: Matrix เพิ่ม Metric **สัปดาห์ OOS (13W)** (รวม = สัปดาห์ที่มีคู่ค้าใดคู่ค้าหนึ่งขาด)

### R4 ABC-XYZ + Safety Stock แบบสถิติ — สวิตช์ `safetyMode` (`statistical` ใหม่ · `days` เดิม)
- **ABC** (`Calc.abcxyzOf`, คำนวณใหม่ทุก AS OF): มูลค่า Sales Out 52 สัปดาห์ (ต้นทุน) ทุกคู่ค้า เรียงมาก → น้อย · SKU ที่สะสมก่อนหน้า < 80% = **A** · < 95% = **B** · ที่เหลือ **C** (SKU ที่คร่อมเส้นอยู่กลุ่มบน) · N / E ไม่ร่วมจัดอันดับ → A + B + C = 100%
- **XYZ:** CV ของความต้องการรายสัปดาห์ 26 สัปดาห์ (ทุกคู่ค้า) · ≤ 0.5 **X** · ≤ 1.0 **Y** · อื่น ๆ **Z** · เมื่อเปิด R3 สัปดาห์ที่ของขาดของคู่ค้า (และสัปดาห์หลังข้อมูลล่าสุดของคู่ค้านั้น) ใช้ค่าเฉลี่ยสัปดาห์ที่มีของของคู่นั้น
- **N** = ขายมาน้อยกว่า 8 สัปดาห์ · **E** = Clearance / Discontinue
- **Lead Time จริง** (`Calc.leadTimeOf`): PO ที่รับแล้วก่อน AS OF (order_date → received_date) — SKU รับ ≥ 3 ครั้ง ใช้ของ SKU · ไม่ถึงใช้ของ Supplier · ยังไม่ถึงใช้ `lead_time_days` + σLT = 0 พร้อมป้าย **LT ประมาณ** (ชุดสาธิต: SKU 87 · Supplier 25 · ประมาณ 8)
- **SS = Z × √(LT × σd² + d² × σLT²)** (`Calc.safetyStatOf`) · Z จาก Service level ของกลุ่ม (ตารางข้อ 7.2 · N 95% · E 0% = ไม่ตั้ง) · d = Run Rate ต่อวัน (ทั้ง SKU ตามวิธี Run Rate ที่เลือก) · σd = SD รายสัปดาห์ ÷ √7 · ไม่มี Run Rate → SS 0
- **ใช้ SS แทน Run Rate × Safety Days:** ROP = d × LT + SS · Order-by = Stockout − LT − SS (วัน) − Delivery · สถานะ Stockout Risk · **Suggested Qty = d × (LT + 90) + SS − (Stock + Open PO)** ปัด MOQ (สูตรเดิมไม่มี Safety) · LT ที่ใช้ = LT จริง (What-if Lead Time ยังบวกได้)
- **แสดงผล:**
  - ป้ายกลุ่ม (เช่น `AX`) ในตาราง Stock, Drawer, วางแผนสั่งผลิต (และการ์ดมือถือ) · ตัวกรองกลุ่ม (A / B / C / X / Y / Z / N / E) ที่ Stock และวางแผนสั่งผลิต

  - วางแผนสั่งผลิต: คอลัมน์ **กลุ่ม · Service level · SS (ชิ้น / วัน) · LT จริง ± σ** (มีใน Excel ด้วย) · What-if เพิ่ม **Service level ±pp** (−10 ถึง +5 · ใช้ได้เมื่อเลือก Safety Stock แบบสถิติ)

### CR-04 Decisions
- **D1–D14** ตามเอกสาร CR-04 ข้อ 8 ทุกข้อ
- **DC-1** ERP เห็นการ์ด "IV − CN วันนี้" ตาม R2-3 (ยอดเอกสาร ERP) แต่ไม่เห็นการ์ดยอดขาย · แผง E-commerce · "ดูเพิ่ม"
- **DC-2** "รอบประชุม S&OP" ใน 14 วันข้างหน้า = วันปิดรับแก้แผน (วันที่ 20) — ปิดรอบในหน้ารอบ S&OP วันนั้น ไม่มีค่าตั้งวันประชุมแยก
- **DC-3** PO / CN ใน 14 วันข้างหน้า นับจาก AS OF ของ Supply (ปฏิทินเดียวกับหน้าของเข้า) · วันปิดรับแก้แผนนับจากวันนี้
- **DC-4** หน้ารายงานเริ่มที่ "วันนี้" (ปิดยอด IV − CN รายวันเหมือนเดิม) · หน้ารายการอื่นเริ่ม "รอบแผนนี้" (D8) · งานค้างเริ่ม "ทุกวันที่"
- **DC-5** แถบสายงาน Order → Cash นับทุกออเดอร์ในสิทธิ์ และกดแล้วเปิดหน้าคำสั่งซื้อที่ "ทุกวันที่" ให้ตัวเลขตรงกับแท็บ
- **DC-6** ลูกค้าทั้งหมด = ลูกค้าที่มีออเดอร์ในช่วง (รวมที่ยกเลิก) · ยอดซื้อรวม / AOV ไม่รวมยกเลิก และหัก CN ที่ออกแล้ว
- **DC-7** Trend: Run Rate = ค่าเฉลี่ย 13 สัปดาห์ข้างหน้าของเส้นแนวโน้ม ÷ 7 · Projection / Stockout Date ใช้ค่ารายสัปดาห์ (ดู OI-1)
- **DC-8** อัตโนมัติเลือกจาก 4 วิธี (4 สัปดาห์ · 3 เดือน · ผสม · แนวโน้ม) ตามสวิตช์ "ไม่นับช่วงของขาด" ที่ใช้อยู่
- **DC-9** ป้ายขาลงต่อเนื่องคิดจาก Sales Out รวมทุกคู่ค้าของ SKU → Action ประเภทใหม่ "ขาลงต่อเนื่อง · ทบทวนการสั่งผลิต / พิจารณาเรียกคืน" (เจ้าของ Planner)
